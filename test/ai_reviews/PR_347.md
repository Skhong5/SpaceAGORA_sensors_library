## Findings

Author's notes for the reviewer (no P1 or P2 known to the author):

- **Low, semantics: the exception filter is wider.** The driver rethrows any
  `GNCAlgorithmError` unwrapped; the old code rethrew only `RPOPlanningError`. A
  planner whose own code throws some other `GNCAlgorithmError` subtype would now
  surface it directly instead of as `:planner_exception`. No such subtype exists
  besides `RPOPlanningError`.
- **Low, contract: `fail_algorithm_request!` must throw.** If a binding's failure
  function returns, the driver throws an `ArgumentError` naming the binding rather
  than continuing with a rejected result.
- **Low, API:** 14 more exported names under G-2. `install!` gains required
  keywords; it had no methods before this PR.
- **Note: the stream-word types are kept.** `gnc_stream_words` returns the same
  vector type the RPO mapping always returned (`sum` of `UInt32` values widens). The
  runtime seeds `MersenneTwister` from it and stores it as `Vector{UInt32}`, as
  `PlannerRuntime` did. A check showed `MersenneTwister` gives the same stream
  for either element type.

Reviewer to verify:

- **The driver runs the old `request_plan!`'s steps in the same order:**
  1. the request record is pushed before the capability check;
  2. the proposal receives `deepcopy(request)` (and `deepcopy(runtime.product)` for
     a retime);
  3. the result is type-checked, then deep-copied, then validated;
  4. the install record is deep-copied before `install!`;
  5. the runtime is updated after `install!`;
  6. the record is pushed last.
- **Failure calls are unchanged:** the capability refusal fails without details;
  the validation refusal fails with `(termination, diagnostics, validation)`;
  exceptions fail with `:planner_exception`, the cause and the backtrace.
- **`GA.install!` for `RPOPlanBuffer` builds the same `RPOPlan`:** copies of the
  reference arrays, `cost=NaN`, diagnostics `(request_id, validation,
  planner=deepcopy(diagnostics))`, then `update_rpo_plan_buffer!`.
- **The controller-lookup scans are untouched,** as agreed for PR 7.
