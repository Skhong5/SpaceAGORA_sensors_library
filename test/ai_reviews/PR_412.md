## Findings

Author's notes for the reviewer (no blocking finding known to the author):

- **Low, transitional by design:** at commit A one source revision accepts two HYPR
  versions and two SpaceAGORAEDG families, while every pin still names 0.2.0. Commit
  B narrows each list to the pinned 0.3.0. Between the two, nothing installs 0.3.0
  except the companions' own CI, which pins this commit.
- **Note, lockstep:** EDG #6 and HYPR #8 pin `b9bee0e8e`, so this branch must not be
  rebased or amended; merge `main` in instead (hook design 4.8). Merge with a merge
  commit.
- **Note, manifest:** the only manifest change is `project_hash`. It was computed with
  `Pkg.Types.workspace_resolve_hash`, and `Pkg.instantiate()` offline accepts the
  manifest without re-resolving.
- **Note, the unit test checks the tuple, not a positive `check_provider` call for
  0.3.0:** `check_provider` also asks `HYPRSupport` whether another provider is
  active, and in a process where HYPR 0.2.0 is loaded a positive call for 0.3.0 would
  mark the process as conflicted and break later tests. The refusals stay tested.
- **Note, version choice:** each companion takes 0.3.0 (minor), because it drops the
  0.2 core family. SpaceAGORAEDG 0.2.1 would have resolved against `main` without the
  compat change here; the three companions take the same step instead.
