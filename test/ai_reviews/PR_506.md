# Review record: PR 506: merge constellation results from disk

## Scope

Review of the SpaceAGORA `constellation-results-from-disk` branch against main (92f2974a9, 0.6.0). It is stacked on C-4b (`constellation-merged-results`, head 4d64b696d), which is stacked on C-5a (`results-long-layout`, head 1db5a2d01); it contains their commits. This is C-5d of the constellations program's large-outputs step, built to the accepted design decision D-C5-11.

What changes:

- **`read_constellation_results(results_directory)`** merges the member folders a constellation ensemble wrote into the members and constellation tables of `ConstellationEnsembleResult`, without running anything again.
  - It reads one member at a time and writes `constellation_members.feather` member by member, one record batch each, then reads it in place.
  - It writes `constellation_summary.csv` beside it.
  - It returns `(members, constellation, files)`.
- **`run_constellation_ensemble(merge_results=true)`** writes its members feather with the same per-member writer when it writes results, and its `members` table then reads that file in place (D-C5-11). Without results files it is built in memory as before.
- **The viewer's ensemble export** reads one sample's table at a time. In a folder with `constellation_summary.csv`, it labels members by id, plane and slot and colours them by plane.

## Findings

No P1 or P2 findings.

- **Changed on purpose.**
  - With `merge_results=true` and results written, `members` reads `constellation_members.feather` in place (read-only columns) instead of holding a copy. It holds the same values.
  - The feather has one record batch per member.
  - The viewer's discovery labels a constellation ensemble's members by id, plane and slot and gives their plane as the scalar, when the folder has `constellation_summary.csv`. Folders without it (Monte Carlo campaigns, ensembles run without the keyword) are labelled as before.
- **Design choices for review.**
  - **One schema for every batch.** An Arrow file has one schema, so the members' columns and types are found first: the union in first-seen order, `Union{Missing, T}` for a column some member lacks, `promote_type` across members. This is what the in-memory merge's `append!(...; cols=:union, promote=true)` gives. Each member's rows are then conformed and written.
  - **From disk, a wide member is renamed by prefix.** The save fields' `per_satellite` flags are not in a member's files. A member runs one spacecraft, so its per-spacecraft columns are exactly its `sc1_` ones. Long members need no renaming.
  - **Identity from disk.** Position and id come from the folder name. Plane and slot come from a long member's own rows, or for a wide member from `constellation_summary.csv`, `missing` without it.
  - **Status from disk.** `success`, `error` and `elapsed_s` come from an earlier summary. Without one, `success` says whether the member wrote results, and the other two are `missing`. A member the summary records as failed has no rows, as in the in-memory merge (D-C4-6), even when its partial results files are there.
  - **The viewer** reads each sample's table twice, once for its outline (columns, last time, cadence) and once for its rows, and holds one table at a time. Colouring by plane uses the page's existing scalar, so the renderer needs no change.

## Residual Risk

- **Memory in the ensemble merge.** The members' rows come back from the members in memory and stay there until the merge writes them, so its peak is the members' rows; the merged table itself is not held. `read_constellation_results` holds one member at a time.
- **One member at a time is by construction, not measured.** The writer takes the members from a lazy iterator and writes each before the next is read. No test counts the members in memory.
- **A run-wide save field of a wide member whose column starts with `sc1_`** would be read as a per-spacecraft column from disk. The default fields have no such column.
- **The viewer's labels** change for constellation ensembles that have a summary; scripts that match sample labels by folder name should match `directory` instead.
