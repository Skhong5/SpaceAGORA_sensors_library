# Review record: PR 504: merge a constellation ensemble's results on request

## Scope

Review of the SpaceAGORA `constellation-merged-results` branch against main (92f2974a9, 0.6.0). It is stacked on C-5a (`results-long-layout`, head 1db5a2d01), whose commits it contains. This is C-4b of the constellations program's campaign-results step, built to the accepted design decisions D-C4-1 to D-C4-6, with D-C5-13 for the members table: the members are built with C-5a's long builder, so no `sc1_` prefix is stripped by name.

What changes:

- `run_constellation_ensemble(args; merge_results=true)` returns a `ConstellationEnsembleResult`.
  - `campaign` is the `MonteCarloResult` the call returns without the keyword.
  - `members` has one row per member and saved time, in the long layout's columns.
  - `constellation` has one row per member: identity, folder, status, rows and its last saved row.
  - `files` lists the merged files, written with `results=true`.
- Without the keyword nothing changes.
- Each member runs with `return_results=true` inside a scoped sink, and its final results save puts its long tables there, whichever layout it writes.
- Two refusals run before any member: the solver-metadata pair, and a run-wide save field with a per-spacecraft field's column prefix.

## Findings

No P1 or P2 findings.

- **Changed on purpose.** None for existing calls. `merge_results=true` is new.
- **Design choices for review.**
  - **Built with the long builder (D-C5-13).** The C-4 design stripped `sc1_` from each member's wide table by name, with a collision rule. Instead, a member's tables come from C-5a's builder through a scoped sink set around its run, so which table a field goes to follows its `per_satellite` flag. The sink is filled only at the final save of a run inside an ensemble merge. Every other run builds nothing more, and the member's own files and returned value do not change.
  - **Identity types** are the long layout's: `spacecraft` `Int32`, `spacecraft_id` `Int64`, `plane` and `slot` `Union{Missing, Int16}`. The C-4 draft said `Int`; C-5a's schema decided.
  - **Run-wide fields sit beside the per-spacecraft ones** in the members table, as the C-5 design says a member's run-wide fields belong to it. The C-4 collision rule (keep `sc1_` on a clash) is gone with the stripping. A run-wide save field with a per-spacecraft field's column prefix is refused before any member runs. A name that meets one only once flattened is refused when the tables merge, before any merged file is written.
  - **`member_tag`** is the folder the member used: the unpadded name when it resumed from a checkpoint written by SpaceAGORA 0.4 or earlier.
  - **Members are merged in position order** by walking the runner's samples, which the runners keep sorted by index. Each member's tables are appended as they are reached.
- **Pre-existing, not changed:** save fields passed to an ensemble are built by the caller, and the default ones are sized for the configuration they were built from. A `save_fields` list built from the whole constellation fails in every one-spacecraft member. The tests build the list from a member's configuration.
- **Not in this PR.**
  - The C-3d refusal of bound configuration-level GNC (T10's last case) comes with C-3d, which is not built yet. C-4b now lands before C-3d; both edit `constellation_ensemble.jl`, in different hunks.
  - T14 (the process route) is not added. The member closure lives in SpaceAGORA, so a process worker can run it, but no test starts a process pool for it. The threaded routes and the serial one are tested.

## Tests Added/Updated

New `test/unit/simulation/constellation_results_tests.jl` (82 tests):

- **The default ensemble** returns a `MonteCarloResult` with `nothing` values and writes only the member folders.
- **Each member's rows** equal that member's own run rearranged by `long_table` (an independent path), with its run-wide columns beside them, column by column. The fixture is a Walker 6/3/1 constellation with non-sequential ids plus a spacecraft without a slot, with the scene saved so that a run-wide field is present. No column keeps a `sc<i>_` prefix, and rows are sorted by position, then time.
- **Identity.** Positions, ids, planes and slots are right, with `missing` without a slot. A repeated id stays apart by position.
- **Routes.** Serial, `threads=:auto` and `threads=2` give `isequal` tables. A slow model scoped to member 1 makes it finish last under threads; it still comes first.
- **Trajectories and values.**
  - With `results=false`, under tsit5 and rodas5p, solutions are equal with and without the keyword.
  - Sample values follow the keywords, and with `return_results=true` the value's table is the wide one.
- **Different columns.** Link-pose columns for members with links, `missing` for a one-link member, in first-seen order.
- **A failed member** has a summary row with the error text, `rows=0` and `missing` last-row columns, and no rows. With `fail_fast=true` the call throws and writes no merged file.
- **Files.**
  - The merged files read back equal to the tables, and the member CSVs are byte-identical to an ensemble without the keyword.
  - The viewer's discovery is unchanged.
  - `save_csv=false` writes no members CSV, and `results=false` writes nothing.
- **Refusals before any member runs**, each shown by a counting callback factory that never ran.
- **Names.** A flattened clash is refused at the merge, and a run-wide `clock` field joins the members table.
- **A resumed ensemble** gives each member its whole run, as its own results file holds it.

## Residual Risk

- **Memory.** The merged tables hold every saved row of every member, and each member also builds its long tables once at its final save. The docstring points large campaigns at `SPACEAGORA_RESULTS_THIN_STRIDE` and `SPACEAGORA_RESULTS_FINAL_ONLY`. A merge from disk, one member at a time, is C-5d.
- **The process route** is not exercised by a test (see Findings).
- **C-3d** adds a refusal to the same file; whichever lands second merges main.
- **The public API page** grows by one docstring, within its size limit.
