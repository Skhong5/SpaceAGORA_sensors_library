# Review record: PR 439: the conformance state comparison pairs dictionary keys

## Scope

Review of the `conformance-dict-keys` branch against main (`4f727266b`). It answers
finding 4 (P2) of the outside review of 2026-10-20. The fix is for 0.5.0, where
`checkpoint_round_trip` becomes required.

Defect. `_same_state` is the structural comparison behind the run-level conformance
checks. It decides whether two states are the same:

- whether a model's own state at the end of two runs is the same
  (`_model_run_difference` in `src/interfaces/analysis/conformance/models.jl`);
- whether a restored state matches, through the checkpoint round trip in
  `src/interfaces/analysis/conformance/checkpoints.jl`.

It matches mutable objects one to one in both directions, so aliasing counts as state.
Its dictionary branch, though, looked up `b[k]` with each key `k` of `a`. Keys were
never compared, and they never entered the alias maps. Two outcomes followed, both
reproduced on main and at v0.4.0 (`c4bd7b6ab`):

- False positive. A model's dictionary key and another field share one mutable object.
  A broken restore replaces that sharing with two equal objects, and the comparison
  still returned true. A `Dict` finds the restored key by equal hash, so the check
  passed although the next update through the field no longer shows through the key.
- False negative. A correct `deepcopy` of `(dict=IdDict(k => 3), key=k)` keeps both
  the lookup and the sharing. It compared unequal, because the copy's key is another
  object and an `IdDict` finds keys by identity. A `Dict` whose keys hash by identity
  (a mutable struct without its own `hash`) failed the same way.

Change. Dictionaries are compared by a new `_same_entries`, which pairs the keys of
`a` and `b` one to one. It compares each key like any other state, through the same
alias maps as the values, and then compares the paired values.

- Plain keys (bits values, symbols, strings) carry no identity of their own. Each is
  found by lookup, as before, and is now compared with the key it finds. A `Dict` finds
  `1.0` with `1`, and that is a different key.
- A mutable key the alias maps have already matched elsewhere in the state pairs only
  with its recorded partner.
- Every other key is tried against the unpaired keys of `b`. For a `Dict`, the key it
  looks up to is tried first. Each trial compares the key and then the value, on copies
  of the alias maps, and only a match is committed to the maps.
- An `IdDict` is searched with `a`'s keys only for plain keys, where identity and value
  agree, so its copied mutable keys are found through the pairing. Equal-hash and identity-hashed keys of a `Dict` pair the same way
  whatever the iteration order.

Nothing else in the comparison changes. Arrays, structs, big numbers, strings and the
skipped runtime objects (tasks, locks, IO) are compared as before.

## Findings

Outside review finding 4 (P2) is fixed: both outcomes are now reported correctly. Points
a reviewer should check:

- Low, greedy pairing. Unseen non-plain keys of `a` are paired in iteration order, each
  with the first candidate that matches on its own. Take two keys that are structurally
  identical, hashed by identity, and also referenced later in the state, in different
  places. A pairing that looks right locally could, in principle, conflict with an
  alias met later. The comparison would then report a difference that a different
  pairing would avoid. That error is conservative: it rejects a state, never accepts a
  wrong one. No built-in model holds such keys.
- Low, cost on large dictionaries. Each trial copies the two alias maps, so a dictionary
  with many non-plain keys costs more to compare than before. Plain keys, the usual case
  in model state, go through lookup as before.
- Note, strings. `String` keys count as plain keys; equal strings are the same key to a
  `Dict`, and identity does not matter for an immutable string. Other `AbstractString`
  keys go through the pairing and still compare by value.
- Note, lookup. `getkey` exists only for `Dict` (and `WeakKeyDict`), so a `Dict` gives
  the key it actually holds. Other dictionaries answer `haskey`, which gives back the
  key itself: an `IdDict` finds keys by identity, and other dictionary types keep their
  own lookup for plain keys, as before.
- Accepted earlier and unchanged: `BigFloat` values compare with `isequal`, so precision
  is not part of the compared state.

## P1 Assessment

No P1 findings. The change affects only the dictionary branch of one comparison
function that the conformance checks use. A state with no dictionaries compares exactly
as before. A dictionary with plain keys compares as before, except that a key the
dictionary finds by `isequal` but that differs from it (`1.0` for `1`) is now a
difference.

  never accepts a wrong state.
- Comparing dictionaries with many non-plain keys costs more because of the trial copies
  of the alias maps.
- `BigFloat` precision is still not compared (accepted limitation).
