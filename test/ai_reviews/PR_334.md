## Findings

Author's notes for the reviewer (no P1 or P2 known to the author):

- Low, design: `ReactionWheelMomentumModel` does not select by `x.spacecraft_index`
  in its pure `wrench`. Its docstring says a direct `wrench` evaluates the model
  "without index selection", and wrapper effectors that forward to it rely on
  that. Selection stays in `wrench_caching!`, which the engine calls.
- Low, compatibility: `StateSample` has one more field.
  - The six-field positional form that built a full sample before is kept and
    gives index 0.
  - Code that reads `fieldcount` or `fieldnames` would see one more field.
  - The repository, its examples and tests, and the companions (MuJoCo's
    `StateSample(r, v, m)`) use the keyword or three-argument form (checked by text
    search; nothing reads its field list).
- Note: the plume's five-argument `wrench` and its `wrench_caching!` are unchanged,
  so the engine path for the plume is unchanged.
- Note: `build_state_sample`'s new fourth argument defaults to 0, so the existing
  three-argument calls in tests and probes keep working. Engine sites pass the
  index; the new route probe would catch one that does not.

Reviewer to verify:

  src`).
- The arithmetic at each site is unchanged: only an `Int` is added to a struct
