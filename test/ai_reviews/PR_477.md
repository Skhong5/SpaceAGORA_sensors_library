  C-3a carries D-C3-1 (ticks iterate the scope's positions, reading the scope
  at each tick) and D-C3-3's part for `register_tstops!`.

What it does:
- **The positions a scope ticks.** `_tick_positions(scope, n)` returns the run
  positions `_ticks_for` accepts, in ascending order and each once:
  - `1:n` for `AllSpacecraft()`;
  - the `BoundSpacecraft` indices, as given when they are strictly increasing
    and within the run, and otherwise sorted, deduplicated and filtered;
  - the `CoupledSpacecraft` primary.
- **The tick loops** iterate those positions instead of testing every
  spacecraft:
  - navigation and guidance ticks;
  - the periodic control tick: its ticks, its stop requests, `_ticks_any` and
    the thread decision;
  - the burn scheduler's mounted tick.
- **Scope reads.** The scope is still read at each tick, once per tick instead of
  once per spacecraft. The control tick reads it after the linked producers have
  prepared.
- **`register_tstops!`** is called for each spacecraft in the scope, instead of
  every index (D-C3-3).

Rule: every existing run is bitwise unchanged. The ticks, releases and stop
requests a built-in receives are the ones it received before.

## Findings

- **F1 (design correction, no code).** The C-3 design listed a function barrier
  for guidance and navigation ticks, on the premise that their tick closures
  captured the model untyped and dispatched at run time for every spacecraft.
  That premise is wrong: Julia types a closure's captured variable by the value's
  runtime type, even when the value comes from the configuration's type-erased
  tuple. A closure built that way has the concrete field type and allocates
  nothing per call, the same as one built behind a barrier. The barrier is not in
  this PR, and the design's item is withdrawn.
- **F2 (contract, by decision).** `register_tstops!` was documented as called
  "once for every spacecraft index". It is now called for each spacecraft in the
  scope (D-C3-3).
  - The burn scheduler is the only built-in with a method, and it is
    event-driven: its stops are registered by its own callbacks, which this PR
    does not change.
  - The new tests pin the call set (ticks, then stop requests, per model, in
    scope order).
- **F3 (scope reads).** The scope is read once per tick instead of once per
  spacecraft. A model whose own tick changed its scope used to see the change for
  the remaining spacecraft of that tick; it now sees it from its next tick (see
  Residual Risk).
  - The control tick reads the scope after `before_reference_control!`. A producer
    that retargets its consumer before the tick is followed in the same tick, as
    before (tested, mutant M9).
- No P1 or P2 finding in the change itself.

## Residual Risk

- **A model that changes its own scope inside its tick.** It now sees the new
  scope at its next tick, not for the rest of the current one. No built-in does
  this: the RPO pair's positions are set by its run-start initializers, before
  the first tick. C-3b (D-C3-2) refuses a scope that changes during a run.
- **`register_tstops!` call set** (F2). A user's periodic model that relies on a
  call for spacecraft outside its declared scope sees fewer calls. Its scope
  should name the spacecraft it acts on.
- **Unsorted or repeated `BoundSpacecraft` indices** take the fallback, which
  builds a small vector at each tick. The ticks are the same. A multi-spacecraft
  Apollo descent with indices given out of order is the one built-in case.
- **Thread decisions** now count the spacecraft in scope, so a thread-safe model
  bound to few spacecraft may run serially where it was threaded before. Timing
  only: the ticks are independent by the thread-safety declaration.
- **What still grows with N × models**, by design until the next C-3 PRs: the
  output hooks and per-spacecraft readers (C-3b) and the callback machinery
  (C-3c). The burn scheduler's own callbacks, one shared model with
  per-spacecraft vectors, are O(N) and unchanged.
- **Not run locally:** `builtin_conformance_tests` with the EDG companion, the
  EDG tests under `test/gnc/aerobraking`, the examples smoke and the whole unit
  tree in its own runner. Suites 02, 04 and 05 had not finished locally when this
  record was drafted. Hosted CI runs all of them.
