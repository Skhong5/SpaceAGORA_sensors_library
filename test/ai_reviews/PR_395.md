# Review record: PR 395: EDGServices contract 2.0.0 and the EDG guidance family


## Scope

Review of the `edg-services-contract-2` branch (head `ea63d2023`) against `main` at
`e5cc7d1ed`: `git diff main...edg-services-contract-2`. One commit.

- `EDGServices.CONTRACT_VERSION` goes from 1.0.0 to 2.0.0 (hook design 3.4, decision
  D-12 = b):
  - `guidance_decision!` and `control_decision!` take the EDG state before the
    configuration (D-1);
  - `_edg_environment_state(p, u, t, spacecraft_index)` takes the context first;
  - `_edg_targeting_control_clock(p)` returns the clock the engine reported to the
    EDG state of the call (`gnc_clock_started!`), replacing the configuration scan
    behind `_edg_targeting_control_clock(config, p)` (GNC design 3.3 and 3.6, which
    PR 7 left for this bump);
  - spacecraft indices are named `spacecraft_index`.
- GNC PR 18 (`edg-family-declarations`): the EDG guidance family, its guidance-mode
  capabilities and `consumes_rng = false`, run through `run_algorithm_request!` by the
  generic `AlgorithmGuidance` binding, as the burn-plan family (#375).
- The paired companion change is SpaceAGORAEDG 0.2.0 (C-E1), which pins this head.

## Findings

Author's notes for the reviewer (no blocking finding known to the author):

- **Low, compatibility by design:** this PR alone fails every core CI job that
  installs the gitlinked companion (`optional-edg-installation`, the unit runner and
  suite 00, the examples smoke and coverage), because the gitlink still points at
  SpaceAGORAEDG 0.1.0 (contract 1.0.0) and the compat accepts only 0.2. That is the
  lockstep protocol (hook design 4.8): the gitlink and the `edg` version in
  `packages/OptionalPackages.toml` move in a second commit after the companion PR
  merges.
- **Low, behaviour of direct calls:** prediction kernels called through core's
  compatibility bindings without an EDG state now have no clock and raise an
  `ArgumentError`; before, they read the configuration. Every run path passes the
  state (the two decision services do), so runs are unaffected; the tests that call
  such kernels directly now pass a context with the state's clock (`_edg_clocked`).
  Conversely, a direct call with a configuration that the run's EDG control does not
  hold used to be refused and now predicts on the state's clock.
- **Low, the clock before the solve starts:** the clock period is `NaN` from
  initialization until the solver starts the EDG control clock. An `AlgorithmGuidance`
  makes its first request when the run starts, before that; a targeting run that
  starts inside the atmosphere would have its first targeting plan refused there,
  where the EDG guidance model waits for its first tick. EDG runs start outside the
  atmosphere; the EDG guidance model is unaffected (its first call is a callback tick).
- **Low, record growth:** the generic driver records every request, and an EDG
  request copies the EDG state, so a binding requesting at every guidance tick keeps a
  record per tick over a long campaign. The reference page says so; the EDG guidance
  model keeps no records.
- **Note, ordering:** the binding ticks before the same tick's control (as every
  `AlgorithmGuidance`), while the EDG guidance model in maximum-depletion mode ticks
  after it. The acceptance runs give identical results either way: in that mode the
  guidance only selects the mode the control would select itself.
- **Note, overlap:** GNC PR 1 (#394) adds its family at the same places in
  `docs/make.jl`, `docs/public_api_symbols.jl`, `src/SpaceAGORA.jl` and
  `test/fixtures/conformance_instances.jl`; the conflicts are adjacent insertions,
  resolved by keeping both families.

- **The clock values are unchanged in a run.** The scan returned the configured rate

  and the companion's `src/`.

## Residual Risk

- Out-of-repository EDG providers written for 1.0.0 stop loading against this core
  until they move to 2.0.0; this is the purpose of the exact check, and the reference
  page lists the changes.
- Between the companion merge and this PR's merge, the companion's `main` pins an
  unmerged core commit (hook design 4.8). Merge both in one session, with merge
  commits.
- The family runs one spacecraft per run; extending the binding to several needs a
  per-spacecraft install target, which the generic binding's one-target rule does not
  allow today.
- The native reference benchmark of the companion was not rerun (it needs the
  authorized native inputs); the native-GRAM Odyssey example was.
