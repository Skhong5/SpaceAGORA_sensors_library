# Review record: PR 497: measure only the machine constants something reads

## Scope

Review of the SpaceAGORA `calibration-trim` branch against main `228c1f309`; the head is clean against main `0487e8226` (the v0.6.0 release), and none of its files moved on main since `228c1f309`.
One commit (`c9c5f0f15`), built on PR 487's head, which removed the unwired
RHS-plan predictor, then a merge of main after PR 487 merged; against main it
shows only this change. It is planned for the 0.6.1 patch. It follows the calibration trim
plan (2026-10-21) and Giusy's decisions of 2026-10-22, all as recommended:
- D-T1: the staleness canary goes: `constants_are_current`, `reference_fma_ns`,
  `reference_mem_ns` and the two reference kernels;
- D-T2: files at schema 5 are measured again, with a loader that reads one
  version (schema 6);
- D-T3: `usl_beta_arith` is not saved.

After PR 487, live code reads three of `MachineConstants`' twenty fields: the
predictive campaign planner reads `usl_alpha_base` and `usl_beta_alloc`
(`campaigns/predictive_planner.jl`), and `ensure_machine_constants!` reads
`measured_threads`. `calibrate_machine` still measured the rest for the removed
predictor: the coefficient-touch and SIMD-lane curves, the scalar-item, queue-node,
dispatch and atomic costs, the parallel speedup curve, the bandwidth ladder (and
the last-level cache size it used) and the two reference kernels. The first
`parallel=true` run on a machine paid for all of them.

Change:
- `calibrate_machine` runs the two USL ladders, arithmetic and allocation,
  unchanged. `MachineConstants` keeps `usl_alpha_base`, `usl_beta_alloc`,
  `fingerprint`, `schema_version` and `measured_threads`.
- The constants file holds those five keys and, as before, any `[campaign]`
  table. `load_machine_constants` reads schema 6 only and returns `nothing` for a
  file without one of the two USL terms, so such a file is measured again rather
  than read as zero.
- `CALIBRATION_SCHEMA_VERSION` goes from 5 to 6. A file at 4 or 5 loads as
  `nothing`, so `ensure_machine_constants!` measures again and keeps the file's
  campaign table, the same path PR 485 used for schema 4.
- Removed, as their last caller went: `RateCurve` and `rate_at`;
  `constants_are_current`, `reference_kernel_ns`, `reference_memory_kernel_ns`
  and their kernels; `calib_touch_kernel!`, `calib_scalar_kernel!` with
  `CALIB_SCALAR_FLOPS`, and `calib_stream_kernel!`; the ladders
  `_calibrate_coeff_touch`, `_calibrate_simd_lane`, `_calibrate_scalar_item`,
  `_calibrate_dispatch`, `_calibrate_polyester_dispatch` and
  `_calibrate_parallel_speedup`, with `_llc_bytes`, `_least_squares_line` and
  the knot tables; the bandwidth step of `_calibrate_usl`; and
  `ParallelCost`'s Polyester import, which only the dispatch ladder used.
- Kept from PR 485: `calib_batch_kernel!`'s column wrap and bounds checks,
  unchanged, and its bounds test (see Tests).
- `scripts/calibration/calibrate_machine.jl` reports the spread of the two kept
  terms.
- Prose that PR 487's review left for this change, rewritten for what remains:
  the `MachineConstants` docstring (it described the predictor's rates and the
  canary), the headers of `machine_calibration.jl`, `calibration_kernels.jl` and
  `robust_timing.jl`, the USL comment in `machine_calibration.jl`, and two
  sentences of `timed_min`'s docstring that named the predictor and the removed
  probe. The reference-kernel note and the dispatch-ladder comment go with their
  code. `ensure_machine_constants!`'s docstring drops a measured-duration
  paragraph that described the longer calibration.

## Findings

No P1 or P2 findings in the change. Points a reviewer should check:

- Every run is unchanged. No simulation path calls the calibration; it feeds
  only the routing of `parallel=true` runs, through the two USL terms, and the
  two ladders that measure them are the same code as before.
- Deliberate behaviour change: on a machine that saved constants before this
  change, the first `parallel=true` run in a working directory measures them
  again, as after PR 485. The calibration it runs is shorter: of its former
  measurements, only the two USL ladders remain.
- Low: the removed names lived in the internal module
  `SimulationModel.ParallelCost`, which `SpaceAGORA` does not import, and no page
  documents them. Code that reached into the module for them, or for the removed
  `MachineConstants` fields, now gets an `UndefVarError` or a keyword error.
  Locally no companion or maintained repository names them; a retained audit
  probe from 2026-09-15 in a private repository calls `_llc_bytes` and would
  throw if rerun.
- Low: `scripts/calibration/calibrate_machine.jl --repeats=N` now reports the
  spread of the two kept terms only.
- Low: `timing_noise_floor` loses its only caller in `src`, the removed dispatch
  ladder. It stays exported as part of robust timing, which `timed_min`'s
  docstring points to, and its tests stay.
- The branch merged main `228c1f309` without conflicts, and no open PR touches
  any of its files.

No P1 findings. The change removes measurements that nothing reads and keeps
