## Findings

The previous companion compatibility ranges and five bundled environments
rejected actual core version 0.7.0. The compatibility updates now admit it.
The immutable companion pins are HYPR
`2816df11c86206cc348ec2c4f82732f958f18ad2`, SpaceAGORAEDG
`424d8aa822e4f2d0a710231b86c28a1bc1dfd636`, and SpaceAGORAMuJoCo
`7b5a00318f6883d7cdc7c7e7c0c18830f96ce57f`. Their package versions remain
0.5.0, 0.5.1 and 0.5.0 respectively. Existing tags at those versions do not
contain the new compatibility metadata. Core's setup commands verify and use
the recorded sources; a broad compatibility range alone does not qualify every
revision in it. The companions retain their earlier default core pins.

The compatibility gate now covers all five bundled environments. Initial
coverage exposed an incomplete isolated fixture: it copied only three project
files, producing six failed positive controls. The same failures reproduced
locally. The repair copies the two nested projects and checks incompatible
core bounds and successful restoration for each environment, without weakening
the gate.

MRI compatibility is limited to `~3.0.3`, the 3.0 patch series. Root, test and
examples resolutions retained the same dependency entries. The MRI parent
documents that outer tolerances do not control fast RK4 microstep error and
gives a scalar-decay stability bound; it does not implement a fast-error
controller or promise nonlinear stability. Laser documentation also states
that occultation and field-of-regard boundaries are sampled at accepted steps.

Independent reviews cleared the companion metadata, bundled-environment repair,
fixture correction, documentation changes and parent-tree composition. An AST
comparison after removing docstrings confirmed unchanged runtime function
bodies in the two source files listed above.
