# PR review: require an explicit random stream in GNC planning kernels

## Scope

Review of PR 343 (branch `gnc-required-rng`, head `712bb97ef`) against `main` at
`a946f6c36`: `git diff main...gnc-required-rng`. Two commits.

- `77b84cdbf`: five GNC planning functions lose their `rng=Random.default_rng()`
  default and require an `AbstractRNG`. `plan_robot_arm_motion` requires one only
  for its sampling planner `:hypr`. Tests and probes that relied on the default
  pass a stream.
- `712bb97ef`: a static gate rejects hidden global streams in GNC code.

## Findings

Author's notes for the reviewer (no P1 or P2 known to the author):

- **Medium, API: a public name changes.** `plan_robot_arm_motion` is public
  (`docs/public_api_symbols.jl:319`).
  - Calls with the default planner are unaffected.
  - Calls with `planner=:hypr` and no `rng` now raise `ArgumentError`; before, they
    drew from the task-local stream.
  - `plan_robot_arm_motion_hypr` (public, :320) has its default in the HYPR
    companion; the paired HYPR commit `c208de647` (local, unpushed) removes it.
  - Decided by the PI (G-6 = a, confirmed 2026-10-16 for both public functions):
    required now, no warning window.
- **Low, behaviour: the error type differs.** `rpo_*` callers that omitted `rng`
  get `UndefKeywordError`, not an `ArgumentError`. That is Julia's message for a
  required keyword.
- **Low, consistency:** the HYPR-implemented 4-argument forms keep their defaults
  until the paired HYPR change. Core's tests pass a stream to them, so they work
  with both.
- **Note:** three `default_rng()` defaults outside GNC (asset point-cloud
  sampling) are out of scope and unchanged.

Reviewer to verify:

- **The gate's stream rule is a naming heuristic.** It accepts any draw whose first
  argument's name contains `rng`, and it reads one line at a time. A call split
  after `rand(` would be flagged even if its stream follows on the next line, and
  a stream variable named otherwise would be flagged too. Both are false
  positives, not misses; neither occurs in the scanned roots.

- Every call in `src/` to the five functions passes `rng` (for example
  `rrt.jl:389, 519`; `planner_comparison.jl:250, 313, 355, 430, 590`), so no
  simulation or comparison output changes.
- No remaining `default_rng()` under `src/models/gnc` (`grep -rn default_rng
  src/models/gnc` is empty).
- Required keyword arguments are interleaved with optional ones in the kernel
  signatures; Julia binds them by name, so the order does not matter.
- `plan_robot_arm_motion` checks `rng` before calling the HYPR method, so an
  installation without HYPR now reports the missing stream first. The optional
  core test was updated for that order.
