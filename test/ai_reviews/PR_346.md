# PR346 review: thruster gimbals

## Scope

Review of the SpaceAGORA `thruster-gimbal` branch against main (it was built
on `sensors`, PR #339, merged as ebda48836, and then merged with main). Step
7d of the actuator plan, first part: the gimballed engine; the control
moment gyro follows separately. The code with its tests, the docs, then a
merge of main.

Authorship disclosure: this record was drafted by the author of the PR. The
plan assigns behaviour PRs of the actuator layer an independent reviewer (the
PI, or the second reviewer when available); this record does not replace that
review.

## Findings

No P1 or P2 findings. Points a reviewer should check:

- Low, by design: a gimbal turns the direction about the nozzle location
  (the pivot); the nozzle does not move, and the gimbal's own mass and the
  engine's moving mass are not modelled.
- Low, by design: gimbal angles change at control ticks, between steps, as
  hinge angles do; there is no gimbal dynamics or actuator torque.
- Low: the scene export draws the plume along the thruster's nominal
  direction (the scene geometry is static).
- Low: the Apollo descent controller reads its jets' `direction` for its own
  allocation and is not gimbal-aware (its layout has no gimbals).
- Low, as for hinges: a checkpoint file does not hold gimbal angles; a
  resumed run starts from the angles the spacecraft record holds.

## P1 Assessment

No P1 findings. Without a gimbal the thruster's direction is used as before
(a Boolean guard, not a multiplication by the identity), so the wrench,
allocation and propellant are bitwise unchanged; the comparison below shows
the four fingerprints identical against the base.
