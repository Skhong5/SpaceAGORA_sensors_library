- **Walker layout:** `walker_planes` gives plane `j` the RAAN `raan0 + j * spread / planes`
  (360° for delta, 180° for star), and slot `k` the mean anomaly
  `M0 + k * 360 / s + j * phasing * 360 / total`. That is the Walker `i: t/p/f`
  layout. `phasing` is limited to `0:planes-1`, and `planes` must divide `total`.
- **Builder:** `build_constellation` sets each slot's orbit from its plane with the
  mean anomaly, keeps the factory's `q` and `ang_vel`, numbers the ids from
  `first_id`, and refuses mutable parts shared between slots.
- **Mean anomaly:** `InitialCondition`'s `M` goes through Kepler's equation once, is
  refused together with `ν` or with `e >= 1`, and equals `ν` on a circle. The `ν`
  defaults (0 for `a`/`e`, 180 for `ra`/`rp`) are unchanged.
- **The new field:** `SpacecraftModel` keeps its 16-argument positional form, and
  `_without_gnc` carries `constellation_slot`.
- **Repeated ids:** they warn through `_hook_deprecation` in `run_simulation`
  setup and in `run_constellation_ensemble`. #420 and #421 both keep that helper.
- **Records and merges:** `## Changed Files` lists all 8 `src/**/*.jl` paths.

Coordinator findings (no P1, no P2):

- **P3, ensemble folders of ten or more members change name.** `sat_1_id_1`
  becomes `sat_01_id_1` once an ensemble has ten or more members. A
  `resume_from_checkpoint` run of such an ensemble written before this change
  finds no checkpoint in the new folders. Each member then warns ("no checkpoint
  file was found; starting from initial conditions") and runs again from the
  start. Scripts that read the old folder names stop finding them. Proposed: on
  resume, fall back to the unpadded folder when the padded one has no checkpoint;
  or say so in the release notes and on the constellations page. Fixed in
  `7c5e84867`: on resume, a member with a checkpoint only under its unpadded
  folder resumes from it and keeps writing there, and the padded folder wins
  when both exist. There is a new test (5 checks), and two mutants are caught.
  The page says which ensembles change names. Scripts that read member folders
  by name still need the padded names, so this goes in the release notes too.
- **P3, repeated ids under `--depwarn=error`.** Core's CI jobs that use
  `--depwarn=error` do not repeat an id, and the RPO builder sets ids. But
  SpaceAGORAMuJoCo's tests build two spacecraft with the default id 1
  (`test/common.jl`, `engine_reference`). Its hosted CI passes no depwarn flag, so
  they only warn there. The local `--depwarn=error` companion runs that the
  release lockstep uses would throw once MuJoCo pins a core with this change. The
  contributor kit's workflow also defaults to `--depwarn=error`, so a
  contributor's multi-spacecraft test with default ids fails after a repin.
  Proposed: a MuJoCo follow-up giving its two test spacecraft ids 1 and 2 before
  its next re-pin, and a line in the release notes and in the note to students.
  Page sentence added in `7c5e84867`: a test suite run with `--depwarn=error`
  (contributor-ci.yml's default) fails on repeated ids. The MuJoCo follow-up
  stays with the coordinator.

## Findings

No P1 or P2 findings.

Points a reviewer should check:

- **Bitwise identity.** The engine never reads the new field. The keyword
  `InitialCondition` gives the same values for the arguments it accepted
  before: `Float64(ν)` of a `Float64` is the same value, and `ra`/`rp` are
  converted before the same arithmetic. The id check only warns. The examples
  and fingerprints below confirm it.
- **Low, by design: repeated ids warn.** `id` defaults to 1, so existing
  multi-spacecraft scripts may repeat it. The warning names the repeated ids
  and their positions. Under `--depwarn=error` it throws, like the other
  deprecations. In the chain, suites 01, 04 and 05
  each warn once (a two-spacecraft configuration with both ids 1) and pass; no
  step run under `--depwarn=error` in CI repeats an id (see Evidence).
- **Low: what the fresh-object check sees.** It compares by identity:
  - the spacecraft and its joints;
  - its links, with every mutable field value and device-list element (one
    level into the lists);
  - its attachments, and its GNC effectors.

  Only mutable objects are compared, so immutable values may be shared. An
  immutable effector that wraps mutable state is not detected.
- **Low: the builder replaces what it sets.** A factory's own orbit and id are
  replaced. Its attitude and body rate are kept. The docstring and page say so.
- **Low: Walker altitude is spherical.** `altitude` is measured above the
  equatorial radius `Rp_e`. Oblate apsis altitudes stay with the planet form of
  `InitialCondition`.
- **Low: folder names for ten or more members.** `sat_1_id_1` of a twelve-member
  ensemble becomes `sat_01_id_1`. Ensembles of up to nine members are
  unchanged, and the in-repo tests and probes use those names.
- **Merge note with #434.** The new page linked `laser_interlinks.md`, which
  #434 renamed to `interlinks.md`. Resolved at `60f4555e1`, after merging main
  with #434 (`ba665dc2a`). The docs page list and the public API list are
  edited at lines away from #434's, and `setup.jl` and `execution.jl` at
  different functions.
